# Standalone engine rules

- This branch contains only the portable engine, MIT typing dictionaries with conventional POS codes, documentation, engine regression tests and a small local web manager. Keep the full app Studio, native apps, public services, artwork, models, databases, private research and credentials out of this tree. The local manager has only Typing, Sound map and Word list. Word list edits the shared compiled dictionary pair through the local server, retaining stable word identities and matching-pair validation. Keep only the current dictionary files; do not retain automatic backups or persistent change history. Temporary transaction files must be cleaned after a save or recovery. Previous browser additions stay active until explicitly imported; never import them automatically or delete words during migration.
- Conversion and ranking rules belong in Rust. Word parts and shared nasal boundaries use the registries in `data/khmer-sound-map.json`; retain each case's scope and order. Node and browser code are thin adapters with no runtime package dependencies.
- Partial component analysis lives in `rust/src/components.rs`. Preserve saved component definitions and unresolved alternatives. Complete, unique splits may supply additive component-word readings and reorder context suggestions through cached runtime indexes; skip partial, ambiguous and Standalone choices, and keep saved definitions authoritative. Owner edits travel in pair provenance and invalidate the runtime cache. Keep compact typing/context bytes, readings, stored ranks, aliases and vocabulary unchanged.
- Repository cleanup must preserve every bundled word, ID, alias, rank, commonness value, POS label, typing policy and typing result. Keep dictionary pair validation and required dependency notices.
- Keep meanings, translations and source evidence out of the distributed dictionaries. Missing POS remains unknown. Do not resume the stopped rich metadata rewrite.
- Preserve the current app/Studio workspace when working on this isolated branch. Do not build or modify mobile apps for engine-only work.
- Use isolated fixtures for tests. Use the scripts in `package.json` for builds and checks. Keep this file short.
- Keep README.md (Khmer, the default) and README.en.md aligned as plain-language guides to word suggestions with minimal setup. Technical details belong in source, types and tests; do not append implementation history or an API manual.

- Small dictionary additions use `npm run dict:add` and `npm run test:dictionary`; input fields are validated in `scripts/add-word.mjs`. Rebuild Wasm only when Rust or rule data changes. For a rule change, run its focused native test and the dictionary checks; reserve full native/manager suites and exhaustive input comparisons for broad changes, failures or explicit reviews. Do not create one-off admission scripts or audit reports for routine additions.
